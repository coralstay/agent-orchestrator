# 2.02 도메인 모델

> 작성 전

agent-orchestrator가 다루는 개념과 그 관계 · 상태.

## 담을 내용

- [ ] 태스크 카드 — 상태(To Do · In Progress · Done), 담당자, 의존, AC, 대상 파일, Token Budget
- [ ] Token Budget — `estimated` · `attempt n` · `actual`, 단위 `in=N out=M`, 토큰 계량 컴포넌트(이름 미정) 값과 `session` 병기. 계량 값의 형식은 `TBD(최상위 Q-18)` (최상위 ADR-021)
- [ ] 세션 — admit → attach → retire 수명 주기와 동시성 허가
- [ ] 실행 가능 판정 — `status = To Do` ∧ 직접 의존 전부 Done ∧ 계획 승인 있음 ∧ 작업 순서 파일 최신, 사람 락(`In Progress` + 사람 담당)과 에이전트 실행분(`In Progress` + `@claude`)의 구분
- [ ] 계획 승인 — claim(`To Do` → `In Progress`) 전에 사람 서명자(`humanSigners`)가 서명한 빈 커밋 `Plan-Approved: <ID>`가 main HEAD에서 닿아야 한다. 승인 게이트의 판정 기준은 최상위 2.02 구현 계획 형식 · 상태와 전이를 가리키기만 하고 옮겨 적지 않는다 (최상위 ADR-022 · BL-017). 승인 없는 카드는 실행 가능 판정에서 빠진다(설계 요구, 구현은 별도 카드)
- [ ] 작업 순서 — 실행 순서는 `backlog/work-order.md`의 단계(같은 단계 = 병렬, 단계 사이 = 순차)와 맞아야 하고, 파일이 낡았으면(첫 줄 해시 불일치) claim하지 않는다 (최상위 2.02 전이와 커밋, BL-016 · RAIL-023)
- [ ] 전이와 커밋 — 오케스트레이터가 직접 하는 커밋의 단계 대응: claim = 착수 단계(그 카드 파일만), 실제치 기록 = 태스크 브랜치의 카드 파일만. 단계 목록은 최상위 2.02 전이와 커밋 (최상위 ADR-023)
- [ ] worktree · 태스크 브랜치 `task/<id>`

# 2.02 도메인 모델

> 작성 전

agent-orchestrator가 다루는 개념과 그 관계 · 상태.

## 담을 내용

- [ ] 태스크 카드 — 상태(To Do · In Progress · Done), 담당자, 의존, AC, 대상 파일, Token Budget
- [ ] Token Budget — `estimated` · `attempt n` · `actual`, 단위 `in=N out=M`, 토큰 계량 컴포넌트(이름 미정) 값과 `session` 병기. 계량 값의 형식은 `TBD(최상위 Q-18)`이고, 그때까지는 `session`만 적는다 (최상위 ADR-021, decision-8)
- [ ] 세션 — admit → attach → retire 수명 주기와 동시성 허가
- [ ] 실행 가능 판정(배정 조건) — `isReady` ∧ `status = To Do` ∧ 미병합 `task/<id>` 브랜치 없음(로컬 · 원격, 병합 여부는 `git cherry`). 사람이 착수해도 브랜치가 생기므로 사람 · 에이전트 착수를 구분하지 않는다 (최상위 ORC-005, decision-14)
- [ ] 착수 — 미병합 `task/<id>` 브랜치의 존재. 카드의 `To Do` → `In Progress` 전환은 에이전트 세션이 그 브랜치에서 하는 기록이고, 전환 실패는 '착수 안 됨'으로 회수한다. 계획 승인 · 작업 순서는 claude-code-agile-hooks가 브랜치 생성 · 전환 때와 세션의 `In Progress` 전환 때 검사하고(오케스트레이터의 `git worktree add`는 훅을 거치지 않는다) 오케스트레이터는 판정하지 않는다 (최상위 2.02 상태와 전이를 가리키기만 하고 옮겨 적지 않는다, decision-14)
- [ ] 전이와 커밋 — 오케스트레이터가 직접 하는 커밋은 실제치 기록뿐이고 태스크 브랜치의 카드 파일만 넣는다. 단계 목록은 최상위 2.02 전이와 커밋 (최상위 ADR-023)
- [ ] worktree · 태스크 브랜치 `task/<id>`

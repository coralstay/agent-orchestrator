# 2.03 기능 요구사항

> 작성 전

agent-orchestrator가 만족해야 하는 기능 요구사항. 최상위 ORC를 같은 ID로 이어받는다.

## 담을 내용

- [ ] 최상위 ORC-001 ~ ORC-031 이어받기 표 — ID · 요구사항 · 이 저장소에서의 범위(다룸 · 범위 밖)
  - ORC-021 — 토큰 집계의 출처는 토큰 계량 컴포넌트(이름 미정)다. 커밋 트레일러에서 읽는 것은 함수별 작업 내역뿐이다. 토큰 출처 `TBD(최상위 Q-18)`, 기록 형식 `TBD(최상위 Q-20)` (최상위 ADR-021)
  - ORC-005 — 배정 조건 `isReady ∧ status = To Do`에 더해, claim은 최상위 BL-017(계획 승인)과 RAIL-023(최신 작업 순서)이 요구하는 착수 조건을 만족해야 한다 (최상위 2.02 상태와 전이)
- [ ] 이 저장소에 닿는 최상위 BL 요구사항 — BL-016(작업 순서 파일 · 같은 단계 = 병렬) · BL-017(계획 → 리뷰 → 계획 승인 뒤에만 `In Progress`). 오케스트레이터의 claim이 착수 전이이므로 둘을 지켜야 한다. 강제는 claude-code-agile-hooks가 에이전트 세션 안에서 하지만(RAIL-020 · RAIL-023, TASK-60 · TASK-64), claim은 세션 밖이라 오케스트레이터가 같은 기준으로 판정해야 한다 — 설계 요구이고 구현은 별도 카드다
- [ ] 세분 요구사항 `ORC-nnn.m` — 예: 카드 Token Budget 검증, claim 커밋(승인 · 작업 순서 확인, 그 카드 파일만 커밋), `attempt` · `actual` 기록, 모델 선택. 하위 번호를 두지 않는 규칙(0 문서 정보)에 따라, 필요하면 최상위 2.03에 새 번호로 올린다
- [ ] 요구사항마다 수용 기준(4.02) 연결

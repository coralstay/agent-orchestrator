# 2.03 기능 요구사항

> 작성 전

agent-orchestrator가 만족해야 하는 기능 요구사항. 최상위 ORC를 같은 ID로 이어받는다.

## 담을 내용

- [ ] 최상위 ORC-001 ~ ORC-031 이어받기 표 — ID · 요구사항 · 이 저장소에서의 범위(다룸 · 범위 밖)
  - ORC-021 — 토큰 집계의 출처는 토큰 계량 컴포넌트(이름 미정)다. 커밋 트레일러에서 읽는 것은 함수별 작업 내역뿐이다. 토큰 출처 `TBD(최상위 Q-18)`, 기록 형식 `TBD(최상위 Q-20)` (최상위 ADR-021). 그때까지는 헤드리스 JSON `usage`(`session`, `ClaudeCodeRunner`)만 기록한다 — 최상위에 ADR-021의 예외로 기록돼 있다 (decision-8)
  - ORC-005 — 배정 조건 `isReady ∧ status = To Do ∧ 미병합 task/<ID> 브랜치 없음`(로컬 · 원격, 병합 여부는 `git cherry`). 오케스트레이터는 작업 순서 파일을 읽지 않는다 (최상위 2.02 상태와 전이, decision-14)
- [ ] 이 저장소에 닿는 최상위 BL 요구사항 — BL-016(작업 순서 · 같은 단계 = 병렬) · BL-017(계획 → 리뷰 → 계획 승인 뒤에만 착수). 둘 다 claude-code-agile-hooks가 `task/<ID>` 브랜치 생성 · 전환 때와 `backlog task edit <ID> -s "In Progress"` 때 강제한다(RAIL-020 · RAIL-023). 오케스트레이터의 `git worktree add`는 훅을 거치지 않으므로 오케스트레이터 실행분은 세션의 `In Progress` 전환에서 검사된다. 오케스트레이터는 훅을 모르고, 에이전트 세션의 착수가 막히면 '착수 안 됨'으로 회수할 뿐이다 (decision-14)
- [ ] 세분 요구사항 `ORC-nnn.m` — 예: 카드 Token Budget 검증, 미병합 `task/<ID>` 브랜치 확인, `attempt` · `actual` 기록(그 카드 파일만 커밋), 모델 선택. 하위 번호를 두지 않는 규칙(0 문서 정보)에 따라, 필요하면 최상위 2.03에 새 번호로 올린다
- [ ] 요구사항마다 수용 기준(4.02) 연결

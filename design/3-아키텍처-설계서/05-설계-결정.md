# 3.05 설계 결정

> 작성 전

이 저장소의 설계 결정과 그 근거 · 기각한 대안. 원본은 backlog 결정(`decision-N`)이다.

## 담을 내용

- [ ] 결정 목록 표 — decision-N · 제목 · 상태 · 관련 원칙 · 요구사항
- [ ] 결정마다 맥락 · 결정 · 기각한 대안 · 결과
- [ ] 최상위 ADR · 요구사항과 어긋나는 결정 — decision-7(최상위 ORC-023 · 3.03 §1 다른 프로바이더)
  - decision-5(토큰은 커밋 트레일러 `Tokens-Used`만 읽는다) — 최상위 ADR-021 · ORC-021로 트레일러가 없어져, 트레일러 합산(`CommitLedger`, AO-6)을 최상위 Q-18 이후로 보류하도록 개정했다(2026-10-29). 직접 커밋은 실제치 기록뿐이고 `AI_AGENT` · `CLAUDE_CODE_SESSION_ID` · `CLAUDE_PID`를 지운다(coding-agent-git-commit-tool GF-130 대비)
  - decision-8(실제치 `commits` = 트레일러 합계 · `session` 병기) — `commits`는 Q-18 이후로 보류하는 단서를 달았다. 그때까지 `session`(헤드리스 JSON, `ClaudeCodeRunner`)만 기록하고, 이것은 최상위에 ADR-021의 예외로 기록돼 있다
- [ ] 대체된 결정 — decision-10(key=value 설정 파일)은 decision-12(정책은 자바 코드, 최상위 ORC-010 · ADR-003과 일치)로 대체됨
  - decision-9(main 카드 착수 커밋 · `In Progress` 담당자 판정)는 decision-14(착수 = 미병합 `task/<ID>` 브랜치, `In Progress` 전환은 에이전트 세션이 태스크 브랜치에서, 중복 실행은 `SessionRegistry` 자체 잠금)로 대체됨. 계획 승인 · 작업 순서는 claude-code-agile-hooks가 브랜치 생성 때 검사하고 오케스트레이터는 모른다 (최상위 ORC-005 · TASK-19)

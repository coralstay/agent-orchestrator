# 3.02 동작 명세

> 작성 전

`run <taskId>` 한 번이 어떤 순서로 무엇을 하는가.

## 담을 내용

- [ ] 실행 순서 — 카드 읽기 · 검증 → 실행 가능 판정(`isReady` ∧ `status = To Do` ∧ 미병합 `task/<id>` 브랜치 없음) → 자체 잠금(`SessionRegistry.admit`) → 모델 선택 → worktree(main HEAD에서 `task/<id>`) → 스폰 · 대기 → 실제치 기록 → 브랜치 상태 판정 → 회수 (decision-14)
- [ ] 착수 판정 — 미병합 `task/<id>` 브랜치를 로컬 · 원격에서 찾고, 병합 여부는 `git cherry`로 본다. 브랜치가 있으면 사람이든 에이전트든 이미 착수한 것이라 배정하지 않는다. 오케스트레이터는 작업 순서 파일과 계획 승인 커밋을 읽지 않는다 — claude-code-agile-hooks가 브랜치 생성 · 전환 때와 세션의 `In Progress` 전환 때 검사한다. 오케스트레이터가 만드는 브랜치(`git worktree add`)는 훅을 거치지 않으므로 오케스트레이터 실행분의 검사 지점은 세션의 전환이고, 막히면 '착수 안 됨'으로 회수한다 (최상위 ORC-005, decision-14)
- [ ] 착수 전환 — 카드를 `In Progress`로 바꾸는 것은 에이전트 세션이 태스크 브랜치에서 한다. 오케스트레이터는 main의 카드를 고치지 않는다. 같은 카드의 중복 실행은 `SessionRegistry.admit`(`putIfAbsent`)이 막는다
- [ ] 단계별 커밋 — 오케스트레이터가 직접 하는 커밋은 실제치 기록(태스크 브랜치)뿐이고, 그 카드 파일만 넣고 push하지 않는다. `AI_AGENT` · `CLAUDE_CODE_SESSION_ID` · `CLAUDE_PID`를 지우고 실행한다 (최상위 ADR-023 · RAIL-021, decision-5)
- [ ] 실패 경로 — 타임아웃, 비정상 종료, 카드 형식 오류, worktree 미커밋 변경, '착수 안 됨'(세션이 `In Progress` 전환에 실패 — 훅이 막은 경우 포함, 사유는 해석하지 않음), 토큰 계량 값 없음(`TBD(최상위 Q-18)`, 그때까지 `session`만 기록)
- [ ] 회수 — 자손 스냅샷 → SIGTERM → 유예 → SIGKILL, Registry 제거, 허가 반납
- [ ] 시퀀스 다이어그램(mermaid)

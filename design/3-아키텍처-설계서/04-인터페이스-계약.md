# 3.04 인터페이스 계약

> 작성 전

agent-orchestrator가 바깥과 주고받는 형식.

## 담을 내용

- [ ] CLI — `orchestrator run <taskId>`, 종료 코드(usage 오류 2)
- [ ] backlog.md CLI — `task view <id> --plain` 출력 형식, 상태 · 의존 · AC 판독
- [ ] 카드 계약에서 이 저장소가 읽고 쓰는 필드 — 최상위 3.04 §1을 가리킨다. claim(`-s "In Progress"` + 담당자 `@claude`)은 최상위 3.04 §3 착수 조건(작성된 계획 · AC · DoD + 계획 승인 + 최신 작업 순서)을 만족한 카드에만 한다
- [ ] 계획 승인 커밋 — 제목이 정확히 `Plan-Approved: <ID>`인 서명 커밋, 유효 서명(`%G?` = `G`) ∧ 서명자(`%GS`) ∈ `humanSigners`. 판정 기준은 최상위 3.04 §1, `humanSigners`의 위치는 최상위 3.04 §7(claude-code-agile-hooks 프로젝트 설정). 오케스트레이터는 이 커밋을 만들지 않고 읽기만 한다 (최상위 ADR-022)
- [ ] 작업 순서 파일 — `backlog/work-order.md`(첫 줄 해시 · 단계별 표, 같은 단계 = 병렬). 형식은 최상위 2.02 전이와 커밋 · 3.04 §3, 구현은 claude-code-agile-hooks TASK-60(draft 포함은 TASK-64, 아직 구현 전) (최상위 ADR-023 · BL-016 · RAIL-023)
- [ ] 오케스트레이터가 직접 하는 커밋 — claim 커밋과 실제치 기록 커밋, 둘 다 그 카드 파일만, push 없음. 제목 · 트레일러는 최상위 3.04 §2 (최상위 ADR-023 · RAIL-021)
- [ ] 에이전트 프로세스 argv — `claude -p <prompt> --permission-mode … --model …`, 금지 플래그
- [ ] 헤드리스 JSON(`--output-format json`)의 `session_id` · `usage`
- [ ] 커밋 트레일러 — 최상위 3.04 §2. 커밋 트레일러에서는 함수별 작업 내역만 읽는다. 토큰 트레일러는 없다 — coding-agent-git-commit-tool은 포맷 레이어다 (최상위 ADR-021)
- [ ] 토큰 계량 컴포넌트(이름 미정)에서 실제치를 읽는 계약 — `TBD(최상위 Q-18)`. 카드 기록 형식은 `TBD(최상위 Q-20)` (최상위 ORC-021)
- [ ] 카드 Description `### Token Budget` 소절 형식
- [ ] 정책 계약 — `AllocationPolicy` 인터페이스, 내장 `DefaultAllocationPolicy`(명시적으로 골랐을 때만), 선택 순서 `-Dpolicy.class` → `ServiceLoader`(둘 이상이면 시작 거부), 정책 미지정 · 로딩 실패 시 에러 메시지 + 시작 안 함(폴백 없음), 고른 정책 클래스 정규 이름과 경로 기록, `META-INF/services` 등록 (decision-12)
- [ ] `runs.jsonl` 한 줄 스키마

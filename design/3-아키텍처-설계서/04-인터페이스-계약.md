# 3.04 인터페이스 계약

> 작성 전

agent-orchestrator가 바깥과 주고받는 형식.

## 담을 내용

- [ ] CLI — `orchestrator run <taskId>`, 종료 코드(usage 오류 2)
- [ ] backlog.md CLI — `task view <id> --plain` 출력 형식, 상태 · 의존 · AC 판독
- [ ] 카드 계약에서 이 저장소가 읽고 쓰는 필드 — 최상위 3.04 §1을 가리킨다. 오케스트레이터는 main의 카드를 고치지 않고, `In Progress` 전환은 에이전트 세션이 태스크 브랜치에서 한다 (decision-14)
- [ ] 착수 판정 — 미병합 `task/<ID>` 브랜치(로컬 · 원격)의 존재, 병합 여부는 `git cherry`. 계획 승인 커밋 · 작업 순서 파일은 claude-code-agile-hooks가 브랜치 생성 때 검사하고(최상위 ADR-022 · ADR-023, 3.04 §3) 오케스트레이터는 읽지 않는다 (최상위 ORC-005)
- [ ] 오케스트레이터가 직접 하는 커밋 — 실제치 기록 커밋뿐, 태스크 브랜치의 그 카드 파일만, push 없음. `AI_AGENT` · `CLAUDE_CODE_SESSION_ID` · `CLAUDE_PID`를 지우고 실행한다(지금은 사람 커밋처럼 보이고, '프로그램 커밋' 구분은 coding-agent-git-commit-tool GF-130). 제목 · 트레일러는 최상위 3.04 §2 (최상위 ADR-023 · RAIL-021, decision-5)
- [ ] 에이전트 프로세스 argv — `claude -p <prompt> --permission-mode … --model …`, 금지 플래그
- [ ] 헤드리스 JSON(`--output-format json`)의 `session_id` · `usage` — Q-18 전까지 토큰 실제치의 유일한 출처(`session`, 최상위에 ADR-021의 예외로 기록, decision-8)
- [ ] 커밋 트레일러 — 최상위 3.04 §2. 커밋 트레일러에서는 함수별 작업 내역만 읽는다. 토큰 트레일러는 없다 — coding-agent-git-commit-tool은 포맷 레이어다 (최상위 ADR-021)
- [ ] 토큰 계량 컴포넌트(이름 미정)에서 실제치를 읽는 계약 — `TBD(최상위 Q-18)`. 카드 기록 형식은 `TBD(최상위 Q-20)` (최상위 ORC-021)
- [ ] 카드 Description `### Token Budget` 소절 형식
- [ ] 정책 계약 — `AllocationPolicy` 인터페이스, 내장 `DefaultAllocationPolicy`(명시적으로 골랐을 때만), 선택 순서 `-Dpolicy.class` → `ServiceLoader`(둘 이상이면 시작 거부), 정책 미지정 · 로딩 실패 시 에러 메시지 + 시작 안 함(폴백 없음), 고른 정책 클래스 정규 이름과 경로 기록, `META-INF/services` 등록 (decision-12)
- [ ] `runs.jsonl` 한 줄 스키마
